# ================================================
# Prompt: Generate a Path in the Scene Graph that Avoids Sentinels
# ================================================

# Purpose:
# You are a reasoning agent responsible for planning a safe navigation route
# through a Hierarchical Scene Graph (HSG). The goal is to find a feasible path
# from the starting node to the destination node that minimizes the risk of
# encountering sentinels.

# The HSG represents an environment (e.g., a city) as interconnected nodes such as
# roads, intersections, and buildings. Sentinel nodes represent patrolling agents or hazards.
# The task is to identify a sequence of connected nodes (a path) that:
#   - leads from start to goal,
#   - avoids high-risk (sentinel) nodes when possible,
#   - and provides reasoning about chosen detours or compromises if unavoidable.

# ------------------------------------------------
# Input Variables:

$HSG_JSON:
(A JSON structure representing the hierarchical scene graph.
Each node includes ID, name, type, connectivity_center, and properties.
Edges indicate spatial or navigational relationships.)

$StartNode:
(Name or node_id of the agent's current location.)

$GoalNode:
(Name or node_id of the intended destination.)

$AvoidanceThreshold:
(Float between 0 and 1; sentinel nodes with detection_risk above this threshold
should be avoided unless no alternative exists.)

$ContextGoal:
(Optional short text — e.g., “Find a route for a spy agent to reach the meeting point undetected.”)

# ------------------------------------------------
# Scene Graph Structure Example:

{
  "graph_id": "hsg_001",
  "nodes": {
    "n1": {
      "name": "Central Plaza",
      "type": "area",
      "properties": {"has_sentinel": false, "has_destination": false}
    },
    "n2": {
      "name": "East Alley",
      "type": "road",
      "properties": {"has_sentinel": true, "detection_risk": 0.8}
    },
    "n3": {
      "name": "Library",
      "type": "building",
      "properties": {"has_destination": true}
    }
  },
  "edges": [
    {"from": "n1", "to": "n2", "relation": "connected_to"},
    {"from": "n2", "to": "n3", "relation": "connected_to"},
    {"from": "n1", "to": "n3", "relation": "connected_to"}
  ]
}

# ------------------------------------------------
# Output Requirements:
# Return ONLY a JSON object in one of the following two forms:

# Case 1: Safe path can be found
{
  "status": "success",
  "path": ["node_1", "node_5", "node_8", "destination_node"],
  "avoided": ["sentinel_1", "restricted_zone"],
  "description": "A safe path from current position to destination, avoiding known sentinels."
}

# Case 2: Missing information prevents safe path planning
{
  "status": "incomplete",
  "missing_info": [
    "Need to know if the road between node_3 and node_4 is blocked.",
    "Unknown position of sentinel near Downtown Plaza."
  ],
  "recommended_action": [
    "Perform an overlook() around Downtown Plaza.",
    "Ask via dialogue: 'Is the East Gate open?'"
  ]
}

# ------------------------------------------------

# Reasoning Rules:

1. **Graph Reasoning**

   * Treat edges as navigable connections.
   * You can traverse edges bidirectionally unless otherwise specified.
   * Prefer shorter paths (fewer hops) that minimize cumulative risk.

2. **Sentinel Avoidance**

   * Nodes with `"has_sentinel": true` represent dangerous zones.
   * If `"detection_risk" >= $AvoidanceThreshold`, consider them blocked unless they’re unavoidable.
   * If no path fully avoids sentinels, select the path that *minimizes exposure duration and risk*.

3. **Hierarchical Awareness**

   * Consider parent-child structure: smaller roads or alleys belong to larger districts.
   * You may detour through a sibling node (same parent) if it offers a safer route.

4. **Fallback Behavior**

   * If all paths cross sentinel zones, mark `"estimated_risk"` accordingly and explain trade-offs.
   * Suggest a possible “wait” or “hold” strategy if avoidance is temporarily impossible.

5. **Language Consistency**

   * Use **exact node names** from the HSG.
   * Keep reasoning concise, factual, and relevant to navigation.

4. **When incomplete, identify missing info.**
   - Mention what local subgraphs or areas need to be explored.
   - Specify the area by coordinates in [x_min, y_min, x_max, y_max]. Output values in multiples of 100 only (e.g., 100, -200, 300...). The area should only be 100x100.

5. **Return only valid JSON.**
   - No extra commentary, markdown, or text outside the JSON object.
