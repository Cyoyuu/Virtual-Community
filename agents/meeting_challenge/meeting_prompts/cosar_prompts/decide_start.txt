4. Extract all available **ETA information**, **agent poses**, and **sentinel poses** from the shared conversation history.

### **Part 1: Discussion Decision Rules**

Set `"initiate_discussion": true` if:

- The recently received message clearly indicates **intention to start** or **need to coordinate** a new discussion or meeting place.
- The current discussion appears to have concluded and a new topic or location is emerging.
- The agent is explicitly called upon to make a new decision (“Where should we go next?”, “Let’s regroup”, etc.).
- The message suggests a discussion is ongoing and it need my participation.

Set it to `false` if:

- The message only provides new information (e.g., reporting sentinel sightings, position updates, or ETAs).
- There’s no clear intent or trigger to start a new round of coordination.

---

### **Part 2: Summarize Agent Opinions**

Guidelines:

- Be objective and factual — reflect what each agent has explicitly stated or implied. 
- If an agent hasn’t spoken or is ambiguous, note that (e.g., “undecided”, “waiting for info”). 
- Use clear, concise phrases (under 15 words per agent). 
- Do not invent opinions — only infer from available conversation. 
- Use exact place names from the list, enclosed in <>, e.g., <Central Park>. 
- For agents not speaking, keep their previous opinion.

---

### **Part 3: Check for Full Agreement**

Using the summarized opinions from Step 1, determine if every agent explicitly supports the same location.

Guidelines:

- Be strict: Agreement means unanimous consensus — no exceptions.
- If any agent is “undecided”, “waiting”, or prefers a different location → agreement_reached = false.
- Do not infer or assume compromise. However, if someone has made a finalization and there are no objections in 5 seconds, you can assume an agreement has been reached.
- If one agent did not response for a while (e.g., over 10s), consider the probability of it being caught, in which case it's opinion doesn't matter to the agreement.
- Use exact string matching for place names (e.g., <Central Park> ≠ Central Park).

If all agents prefer the same location, set `"agreement_reached": true` and `"agreed_location"` to that location.
Otherwise, set "agreement_reached": false and `"agreed_location"` to the most supported location.

---

### **Part 4: Information Extraction Rules**

Extract structured information from conversation history and the most recent message:

- **ETA Map**:
  - Keys: Place names from `$Places`, enclosed in `<>`.
  - Values: Sub-objects mapping agent names → ETA strings (`"HH:MM:SS"` format) or `"Impossible"`.
  - Include:
    - Other agents’ ETAs mentioned in the conversation.
  - If multiple ETAs for the same agent–place pair, keep the most recent.
  - Omit places with no ETA.

- **Agent Poses**:
  - Keys: Agent names.
  - Values: `[x, y]` coordinates extracted from the conversation.
  - Example mention: “I’m currently at [-133.75, 62.37]”.

- **Sentinel Poses**:
  - A list of all detected sentinel coordinates extracted from the conversation.
  - Example mention: “I see a sentinel at [-55.0, 176.0, 98.58]”.

Parsing guidelines:
- Only extract numeric ETAs explicitly tied to a **place** and **agent**.
- Use `"Impossible"` for statements like “I can’t reach <Park>”.
- Ignore vague estimates like “soon” or “around 10 minutes” unless a number is clearly stated.
- Match agent names exactly as they appear in `$AgentList`.

---

### **Output Notes**
- Always return **valid JSON** in the format above.
- Be accurate and conservative: include only clearly stated and verifiable information.
- If no ETAs or poses are found, use empty objects/lists (`{}` or `[]`) for those fields.
